# NX500 모딩 생태계 조사 (2026-10-17)

이 문서는 nx500ex 프로젝트를 시작하기 전에, 기존 Samsung NX500 / NX1 모딩 자료가 어디에 있고 무엇을 하는지 한 곳에 정리한 것이다.
조사 방법은 각 GitHub 저장소를 직접 clone 하여 커밋 이력, 스크립트, 바이너리 목록을 읽은 것이며, 포럼(dpreview)은 접근이 차단되어 검색 결과와 2차 자료로만 보충했다.

목차

5. NX-KS 애드온 (별도 설치물)

## 1. 한 줄 결론

- 이름을 정확히 하면, 상류 저장소는 ottokiksmaler/nx500_nx1_modding 이고 NX-KS(KinoSeed 제작) 2.88 의 원본 ZIP 은 nxfiles.nx.tc 미러에만 남아 있다. 이 ZIP 을 git 이력으로 복원한 것이 ge0rg/nx-ks-mod 이다.
- NX-KS 2.88 은 bluetoothd 를 바꿔치기해서 블루투스 ON 시 /opt/usr/nx-ks/init.sh 를 실행하고, keyscan 이 EV+키 조합과 auto/*.sh 를 처리하는 구조다. 기능은 전부 bash 스크립트 + 소형 C 바이너리(mod_gui, popup_*, poker, focus_stack 등)로 되어 있어 분해와 재조합이 쉽다.
- ge0rg 는 2022년부터 상류 저장소에 SSH 서버, stapp, prefman 덤프 파서, DFMS/타임존/펌웨어 알림 문서를 추가했고, 2025년 5월부터는 nx-ks-mod 에서 NX-KS 유지보수를 공식적으로 이어받아(NX-KS3 목표) 벌브 타이머, MODEL 환경변수화, IP 표시 등을 넣었다.
- 2026년 8월부터 WApaperplane/NXWA-nx500_modding 이 매우 활발하다(오늘 날짜 커밋 존재). 필름 시뮬레이션(FilmLab), 3D LUT, Nuklear 기반 UI, 웹 갤러리, 그리고 ISP 코프로세서(p7) 펌웨어 패치까지 손대고 있어서 범위가 가장 넓지만 위험도도 가장 높다.
- SD 카드만으로 동작하는 방식은 존재한다. 다만 "내장 플래시를 전혀 건드리지 않는" 방식은 factory mode(info.tg) 뿐이고 제약이 있다. bluetoothd 한 파일만 바꾸고 나머지는 SD 카드에 두는 절충안이 상류 저장소에 공식 도구로 이미 있다(3장 참고).

## 3. 모드 실행(런칭) 방식 비교

NX500 은 NX300 과 달리 SD 카드의 autoexec.sh 를 자동 실행하지 않는다. 그래서 다음 네 가지 진입점이 쓰인다.

| 방식 | 내장 플래시 변경 | 실행 시점 | 장점 | 단점 |
| --- | --- | --- | --- | --- |
| A. Factory mode (SD 루트에 info.tg + nx_cs.adj + 스크립트) | 없음 | 전원 ON 때 dfmsd 가 nx_cs.adj 를 처리 | 카드 빼면 순정. 상류의 tools/*.zip 과 MultiNX 가 이 방식 | dfmsd 가 터치스크린을 가로막음(killall dfmsd 로 해결), 디버그 오버헤드, 절전 진입 시 SD 언마운트와 함께 프로세스가 죽어 깨어나면 다시 안 뜸 |
| B. bluetoothd 교체, 스크립트는 SD 에 (SD-card-mod-running-mods/run-SD-card-app-on-bluetooth-activation) | /usr/sbin/bluetoothd 한 파일 (원본은 bluetoothd.orig 로 보존) | 블루투스 ON 때 /mnt/mmc/scripts/init.sh 실행 | 변경 최소, 카드 빼면 아무 일도 안 일어남, uninstall 폴더 제공 | 절전 후 keyscan 재시작 필요(BT 가 다시 켜질 때 재실행됨), 블루투스 본 기능은 사용 불가 |
| C. bluetoothd 교체 + 스크립트를 /opt/usr/nx-ks 로 복사 (NX-KS 2.x 방식) | bluetoothd + /opt/usr/nx-ks 디렉터리 | 블루투스 ON 때 init.sh | 절전/하이버네이션에도 keyscan 이 살아 있어 즉시 반응, SD 카드 자유롭게 교체 | 사용자가 꺼린 "내장 설치". 2.00m 이후 prefman 저장을 eMMC 로만 하도록 바뀜 |
| D. nx-on-wake (Vasile) | 하이버네이션 이미지 재생성 (파티션 9) | 콜드/웜 부팅 모두, 블루투스 불필요 | 가장 빠르고 BT 를 정상 사용. SD 의 /nx-on-wake/on-wake 가 있으면 그것을, 없으면 /opt/usr/nx-on-wake/on-wake 를 실행 | 설치가 위험(README 가 "뇌를 끄고 글자 그대로 따르라"고 경고), 제거는 펌웨어 재설치만 가능, ASLR 때문에 구형 비트레이트 모드와 비호환 |

doc/Boot_Process_and_Speeding_up_Mods.md 의 핵심: 카메라는 매번 부팅하는 게 아니라 hybrid-sleep 에서 복귀한다. 전원 스위치 OFF/ON 은 suspend-to-RAM 복귀(빠름), 배터리 분리는 파티션 9 의 RAM 이미지 복귀(느림). di-camera-app 이 절전 전 SD 카드를 언마운트하므로 SD 위에 있던 keyscan 은 죽는다. NX-KS 가 내장 설치를 택한 이유가 바로 이것이다.

사용자 요구(SD 에 있으면 실행, 없으면 순정)에 가장 가까운 것은 B 다. 내장에는 bluetoothd 래퍼 한 개만 남고, 그 래퍼는 SD 의 init.sh 가 없으면 그냥 끝난다. 다만 2.88 의 install.sh 는 블루투스 원본을 실행하지 않는 래퍼를 쓰고(bt.sh 체크박스로 수동 복구), 상류의 BT 문서 버전은 init.sh 실행 후 bluetoothd.orig -d 를 이어서 실행하므로 블루투스가 유지된다. 어느 쪽을 택할지는 설계 단계에서 결정할 일이다.

## 4. NX-KS 2.88 전체 기능 목록

출처: ge0rg/nx-ks-mod 의 커밋 e2c52e2 (NX-KS2.88.zip 그대로) 와 NX-KS_readme.md. 설치 대상 펌웨어는 NX500 1.12, NX1 1.41 로 고정되어 있고 다른 버전은 install.sh 가 거부한다.

### 4.1 설치/구동 구조

- SD 루트의 info.tg -> nx_cs.adj ("shell script /mnt/mmc/install.sh") -> install.sh 자동 실행.
- install.sh 는 bluetoothd 를 bluetoothd.orig 로 옮기고, /opt/usr/nx-ks/init.sh 를 호출하는 래퍼를 쓴다. scripts/ 전체를 /opt/usr/nx-ks/ 에 복사하고 SD 의 설치 파일을 지운 뒤 재부팅한다. 이미 설치되어 있으면 반대로 제거 동작을 한다(두 번 꽂으면 삭제되는 함정이 있어 WApaperplane 이 이 부분을 고쳤다).
- init.sh: 영상 모드(hevc ON)면 끝날 때까지 대기, Tizen 환경변수 설정, MODEL 변수 설정, keyscan /dev/event0 /dev/event1 /opt/usr/nx-ks/ 를 nice +15 로 기동.
- keyscan: 시작 시 auto/*.sh 를 순서대로 실행하고, EV 와 다른 키 조합을 감지하면 EV_<키>.sh 를 실행한다. bbaf, peaking, debug 옵션이 있다.
- auto/a_init.sh: 첫 실행 때 기본 비트레이트(Pro4K 160, ProHD 180, Hq4K 90, HqHD 90, HqVGA 180)를 pokemonche 로 계산해 init_auto.tp 템플릿으로 a_init.sh 를 다시 생성한다. 이후 부팅마다 poker 로 di-camera-app 프로세스 메모리를 직접 패치하고 onscreen_ks (화면 상단 NX-KS 버튼) 를 띄운다.
- mod_gui: 두 열 버튼/체크박스 메뉴. 설정 파일은 gui_*.NX500 / gui_*.NX1. 체크박스 ON 은 스크립트를 실행하고 auto/ 에 복사, OFF 는 auto/ 에서 삭제하고 off_<이름>.sh 실행. 메뉴 파일 앞에 @ 를 붙이면 서브메뉴.

## 6. NX-KS 버전 변천과 2.88 직전 버전과의 차이

- 1.52~1.54: 256MB 스왑 추가 후 제거, readme 추가.
- 1.56~1.60: 포커스 풀 속도, 피킹, Wake Lapse, 리포커스.
- 1.61~1.62: Bug-Zapper, BitRate Booster, popup_entry 기반 새 GUI.
- 1.65~1.67: 프로필 손상 검사, 녹화 중 모드 차단 안전장치, DC 슬롯 2.5K.

- 1.77~1.82: Ramping(bulbramp), ZoomZoom.

## 9. 이 프로젝트에 대한 시사점과 다음 단계

사용자 요구 정리: (1) 여러 저장소에 흩어진 것을 한 곳에서 이해하고 싶다, (2) SD 카드에 있으면 실행되고 없으면 순정인 구조를 원한다, (3) 기능을 추가하고 싶다.

관찰

- 기능 자체는 거의 전부 bash + 소형 ARM 바이너리이고 의존 관계가 단순하다(keyscan -> 스크립트 -> st/prefman/poker). 재구성 비용은 낮다.
- 내장 설치가 선택된 진짜 이유는 절전 시 SD 언마운트로 keyscan 이 죽는 문제와 부팅 속도다. SD 전용으로 가려면 (a) BT 재활성 때 재시작되는 것을 받아들이거나, (b) bluetoothd 래퍼가 SD 마운트를 기다렸다가 init.sh 를 실행하도록 만들거나, (c) 다른 상주 훅을 찾아야 한다.
- poker 로 di-camera-app 메모리를 패치하는 비트레이트/해상도 모드는 펌웨어 1.12 의 고정 오프셋에 의존한다. 펌웨어 버전 확인을 반드시 유지해야 한다.
- 모든 자료가 NX500 1.12 / NX1 1.41 기준이다. 현재 카메라의 펌웨어 버전을 먼저 확인해야 한다(메뉴 > 설정 > 기기 정보, 또는 /etc/version.info).
- WApaperplane 의 p7 펌웨어 패치와 nx-on-wake 의 하이버네이션 이미지 재생성은 "카드 빼면 순정"이라는 요구와 양립하지 않으므로 범위에서 제외하는 것이 맞다.

제안하는 다음 단계

1. 설계 결정: 진입점을 B(bluetoothd 래퍼 1개 + SD 의 scripts/init.sh)로 할지, A(factory mode)로 할지 확정. B 를 택하면 상류의 run-SD-card-app-on-bluetooth-activation install/uninstall 을 그대로 재사용할 수 있다.
2. NX-KS 2.88 스크립트에서 /opt/usr/nx-ks 경로 의존을 제거하고 $DIR 또는 MODDIR 환경변수로 바꾼 SD 전용 레이아웃을 만든다(ge0rg 의 MODEL 변수화와 같은 방향).
3. 바이너리 소스 확보 상태 점검: keyscan, mod_gui, poker, focus_stack, focus_buttons, popup_*, shutter_to_key, log_watcher, mod_lapse, stapp, onscreen_key, button_png 는 상류에 C 소스가 있다. onscreen_235, onscreen_ks, onscreen_ov, onscreen_rc, rem_gui, blackout, poker2 는 2.88 ZIP 에 바이너리만 있다(onscreen_key.c 에서 파생된 것으로 추정되며 재빌드 또는 대체 필요).
4. 크로스컴파일 환경 결정: 상류는 arm-linux-gnueabi(hf) gcc 와 NX300 GPL 소스의 sbs 툴체인, WApaperplane 은 zig 0.13 -target arm-linux-gnueabi.2.15 -O0, mewlips 는 buildroot 를 썼다.
5. 추가 기능 후보를 정하기 전에, 2.88 의 각 기능을 SD 전용 레이아웃에서 하나씩 동작 확인하는 체크리스트를 만든다.

# 단계 1 설계안: 진입 훅과 SD 구조

진단 결과(docs/research/2026-10-18-probe-result.md)와 2026-10-18 결정 사항을 반영한 설계다.

## 0. 확정된 결정

| 항목 | 결정 |
| --- | --- |
| 내장 변경 | 최소화. 루트의 bluetoothd 래퍼 한 파일과 원본 이름 변경만. /opt/usr 는 처음에는 쓰지 않음 |
| 스크립트와 바이너리 | 전부 SD 카드에서 읽고 실행 |
| 메뉴 | 당분간 NX-KS 의 mod_gui 와 같은 형식. 불편하면 나중에 교체 |
| 블루투스 | 카메라 설정에서 상시 ON. 래퍼가 원본 bluetoothd 도 실행해 블루투스 기능 유지 |
| NX-KS | 공존 기능은 만들지 않음. 설치기는 이미 다른 래퍼가 있으면 덮어쓰지 않고 멈추기만 함 |
| 실행 순서 | auto 스크립트 번호로 우선순위 지정 (3절) |

## 1. 내장과 SD 의 역할

| 위치 | 들어가는 것 | 크기 | 이유 |
| --- | --- | --- | --- |
| 루트 /usr/sbin/bluetoothd | 래퍼 스크립트 | 1KB 미만 | 카메라가 켤 때 스스로 실행하는 곳은 여기뿐. SD 에는 이런 진입점이 없음 |
| 루트 /usr/sbin/bluetoothd.orig | 삼성 원본 (이름만 바뀜) | 기존 파일 | 블루투스 기능 유지 |
| SD /mnt/mmc/nx500ex/ | 나머지 전부: boot.sh, 바이너리, 키 스크립트, auto 스크립트, 메뉴, 설정, 로그 | | 넣고 빼기 자유 |

/opt/usr 를 쓰는 건 기능상 필수가 아니라 속도를 위한 선택이다 (2절의 단점 참고). 처음에는 쓰지 않고, 실기 측정 후 필요하면 keyscan 하나만 옮긴다.

## 2. 왜 NX-KS 는 내장에 넣었고, 우리는 왜 안 넣어도 되는가

- 전원 OFF 직전에 카메라 앱이 SD 카드를 언마운트하면서, SD 에서 실행 중인 프로그램(keyscan 등)은 모두 종료된다.
- 다시 켜면 블루투스가 켜져 있던 카메라는 bluetoothd 를 다시 시작한다 (상류 Boot_Process 문서). 즉 래퍼가 켤 때마다 다시 불린다.
- 그래서 SD 에서 실행해도 켤 때마다 keyscan 이 다시 올라온다. 대가는 bluetoothd 시작과 SD 마운트를 기다리는 몇 초의 지연이다.
- NX-KS 는 이 지연을 없애려고 내장에 넣었다. 내장의 keyscan 은 OFF 중에도 메모리에 남아 켜는 즉시 동작한다.

검증할 가정: "켤 때마다 bluetoothd 가 다시 시작된다". 첫 실기 테스트에서 확인한다. 성립하지 않으면 keyscan 하나(약 14KB)만 /opt/usr/nx500ex 에 둔다.

## 3. 실행 순서와 우선순위

대부분의 기능은 키 조합이나 메뉴로 부를 때만 실행되므로 켤 때 로딩이 없다. 켤 때 실행되는 것은 auto 폴더의 스크립트뿐이다. 이것만 순서를 정하면 된다.

켤 때 일어나는 일

```
전원 ON
  -> bluetoothd 시작 (래퍼)
  -> SD 마운트 대기
  -> keyscan 시작 (SD 의 바이너리)        여기서부터 키 조합 사용 가능
  -> auto/*.sh 번호 순 실행
```

auto 번호 규칙

| 번호대 | 성격 | 들어갈 것 | 방식 |
| --- | --- | --- | --- |
| 00~09 | 켜자마자 필요한 설정 | 무음 전자셔터, 렌즈 미인식 촬영 | 한 줄짜리. 순서대로 즉시 실행 |
| 10~19 | 가벼운 상태 복원 | 사용자 체크박스, 지속 피킹 플래그, 터치 상태 | 즉시 실행 |
| 20~49 | 화면 표시 | 화면 상단 메뉴 버튼, PNG 오버레이 | 상주 프로그램. 백그라운드로 띄움 |
| 50~79 | 예약 작업 | Wake Lapse 의 재개 등 | 해당 작업이 걸려 있을 때만 |
| 80~99 | 느려도 되는 서비스 | telnet/FTP, SSH, 웹 원격 서버 | 백그라운드, WiFi 연결 확인 후 시작. 카메라 반응을 막지 않게 낮은 우선순위(nice) |

부를 때만 실행되는 것 (로딩 없음)

| 진입 | 기능 |
| --- | --- |
| 키 조합 | 메뉴, 셀프타이머, AF-S/AF-C 토글, 터치 토글, 프로필 불러오기 |
| 메뉴 | HDR, ZoomZoom, 벌브, 포커스 스태킹, 타임랩스, FilmLab, LUT 적용, 설정 백업/복원, 셔터 횟수, 스크린샷, PTP |

## 4. 래퍼

```sh
#!/bin/sh
# nx500ex bluetoothd wrapper
(
  i=0
  while [ $i -lt 30 ] && [ ! -x /mnt/mmc/nx500ex/boot.sh ]; do sleep 1; i=$((i+1)); done
  [ -x /mnt/mmc/nx500ex/boot.sh ] && [ ! -e /mnt/mmc/nx500ex/DISABLE ] && /mnt/mmc/nx500ex/boot.sh
) </dev/null >/dev/null 2>&1 &
exec /usr/sbin/bluetoothd.orig "$@"
```

- SD 가 없으면 30초 기다리다 조용히 끝난다. 원본 bluetoothd 는 항상 바로 실행된다.
- boot.sh 를 SD 에 두므로, 래퍼 이후의 모든 동작은 PC 에서 SD 파일만 고쳐서 바꿀 수 있다. 래퍼는 한 번 설치하면 다시 건드릴 일이 없게 만든다.
- SD 의 exFAT 은 실행 권한을 그대로 준다 (진단 결과의 마운트 옵션 fmask=0022 확인).

## 5. SD 구조

```
/mnt/mmc/nx500ex/
    boot.sh            래퍼가 부름. keyscan 시작
    bin/               keyscan, mod_gui, popup_timeout, popup_ok, popup_entry, poker, stapp, busybox, telnetd
    scripts/           EV_EV.sh, EV_OK.sh 등 키 조합
    scripts/auto/      00_silent.sh ... 85_telnet.sh
    menu/              메뉴 정의 (NX-KS gui_*.NX500 형식)
    conf/              설정값
    log/               실행 기록
    DISABLE            있으면 아무것도 안 함 (안전 모드)
```

## 6. 설치기와 제거기

설치 패키지 (factory mode 로 한 번 실행)

1. NX500 1.12 가 아니면 중단.
2. bluetoothd 가 원본(ELF, 332440 바이트)이고 bluetoothd.orig 가 없을 때만 진행. 이미 우리 래퍼면 래퍼만 갱신. 그 밖의 상태(NX-KS 등 다른 래퍼)면 아무것도 바꾸지 않고 화면에 알린 뒤 중단.
3. 루트를 읽기쓰기로 다시 마운트, 원본 이름 변경, 래퍼 작성, sync, 읽기 전용으로 복귀.
4. 결과를 SD 로그와 화면에 표시하고 info.tg 를 info.tg.done 으로 바꿈.

두 번 실행해도 제거되지 않는다. 제거 패키지는 bluetoothd.orig 를 원래 이름으로 되돌린다. 펌웨어 재설치로도 원복된다.

## 7. 첫 검증 순서

1. 설치 패키지 실행 후 진단 패키지로 래퍼와 원본 보존 확인.
2. 카메라 설정에서 블루투스 ON.
3. SD 의 auto 에 AF 보조광을 1초 켜는 스크립트 하나만 두고 콜드 부팅. 불이 들어오면 전체 경로 동작.
4. 전원 OFF/ON 을 여러 번 반복해 매번 불이 들어오는지, ON 후 몇 초 걸리는지 측정. 2절의 가정 검증.
5. EV+반셔터에 같은 스크립트를 걸어 키 조합 확인.
6. DISABLE 파일로 안전 모드 확인. SD 를 빼고 켜서 순정 동작 확인.
7. 제거 패키지 실행 후 순정 복귀 확인.

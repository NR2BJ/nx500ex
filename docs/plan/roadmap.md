# nx500ex 로드맵 (2026-11-04 재작성)

두 판으로 나눈다. 안전판은 플래시를 건드리지 않는 모든 것 (SD 전용 + 실행 중인 카메라 앱에 끼어들기) 이고, 파괴판은 안전판이 다 된 뒤에 플래시와 펌웨어를 손대는 실험이다. 언제 할지는 정하지 않는다. 무엇을 할지와 순서만 적는다. 이전 로드맵과 진행 내력은 docs/plan/old/roadmap-2026-10-26.md 에 있다.

## 0. 원칙

안전판

1. 내장 변경은 블루투스 래퍼 한 파일과 원본 이름 변경으로 한정한다. 나머지는 전부 SD. 카드를 빼면 순정.
2. 하이버네이션 스냅샷 재생성, 파티션 쓰기, p7 (카메라 앱) 패치는 하지 않는다. 실행 중 프로세스에 끼어드는 것 (주입, 훅) 은 메모리에만 남으므로 안전판에 든다.
3. 키 감지, 메뉴, 서버 같은 프로그램도 SD 에서 실행한다. 켤 때마다 래퍼가 다시 띄운다.
4. SD 에 기록하는 스크립트는 쓰기 뒤에 sync 한다.
5. 대상은 NX500 1.12 하나. NX1 은 나중에.
6. 공개 저장소, AGPL-3.0. 상류 (NX-KS, ge0rg, mewlips) 코드는 쓰되 metol 의 LUT 와 레시피 방식은 참고하지 않는다 (개념 구경은 됨).
7. 카메라 조작과 확인은 가능한 한 PC 에서 한다 (FTP, 텔넷, GPIO 셔터, 웹 원격). 발열이 있는 시험 (장노출 반복) 은 짧게.

파괴판

8. 안전장치 (파티션 덤프, 복구 경로 확인) 가 끝나기 전에는 플래시에 아무것도 쓰지 않는다.
9. 한 번에 한 가지만 바꾸고, 바꾸기 전 상태로 돌아오는 방법을 먼저 적는다.

### 2-2. 카메라 앱에 끼어들기 (Magic Lantern 급, 플래시 무수정)

ML 은 펌웨어를 바꾸지 않고 카드에서 올라와 카메라 OS 의 내부 함수를 가로채 쓴다. 우리는 Linux root 이므로 실행 중인 카메라 앱 (di-camera-app) 에 코드를 넣어 (ptrace 주입, 또는 앱을 다시 띄울 수 있으면 LD_PRELOAD) 같은 급으로 갈 수 있다. 메모리에만 남으므로 전원을 다시 켜면 순정이다.

| 순서 | 할 것 | 메모 |
| --- | --- | --- |
| 1 | 조사 (읽기만) | 앱 바이너리와 라이브러리를 가져와 심볼, 구조, 키 처리와 촬영 경로 함수 찾기. ptrace 가 이 커널에서 허용되는지. 앱 재시작이 가능한지 (전원 끄기가 절전 스냅샷이라 어려울 수 있음). 앱이 ISP 에 보내는 명령 (st cap iq 와 같은 통로) 관찰 |
| 2 | 주입 틀 | 주입기와 훅 라이브러리 (zig 정적), 전원 켤 때 래퍼가 올림, 실패하면 아무것도 안 함, 끄는 스위치 |
| 3 | 진짜 백버튼 AF | 반셔터의 AF 호출을 막고 AEL 에 AF |
| 4 | 다이얼, 휠, 터치 이벤트 | 앱이 받는 입력을 우리 메뉴와 동작에도 (다이얼 연속 조절, 터치 AF 좌표 직접 호출) |
| 5 | 트랩 포커스, AF 확인 신호 | 초점 확인 콜백을 가로채 셔터 |
| 6 | 프리캡처 | 앱 안에 풀 해상도 버퍼 경로가 있으면 반셔터 동안 링 버퍼. 없으면 파괴판 |
| 7 | 셔터/녹화 상한과 숨은 설정 | 앱이 거부하는 설정 (다중 노출 PASM, 녹화 제한, 비트레이트) 을 앱 안에서 바꿈 |
| 8 | 메뉴 항목 추가 | 순정 메뉴에 우리 항목을 끼워 넣기 (메뉴 재설계의 다른 길) |
| 9 | 영상 ISP | 앱의 ISP 명령을 보고 영상 샤프닝/NR, 영상 LUT (뱅크가 영상에도 걸리는지), 플랫 프로필 |
| 10 | 그레인과 숨은 효과 | 앱이 안 보여 주는 ISP 효과를 켬 |

# 제거 패키지 (v2)

래퍼를 없애고 원본을 원래 이름으로 되돌린다. v2(bt-stack-up.sh 래퍼)와 v1(bluetoothd 래퍼) 설치 상태를 모두 되돌린다. 원본이 공식 펌웨어 1.12 의 값(체크섬)과 같을 때만 되돌린다.

## 순정 복귀의 범위

| 항목 | 제거 후 |
| --- | --- |
| /usr/etc/bluetooth, /usr/sbin 의 파일 목록 | 설치 전과 같다 |
| 원본 파일의 내용, 크기, 권한, 소유자, 수정 날짜, inode | 같다. 설치 때 이름만 바꿨던 바로 그 파일이다 |
| 폴더(/usr/etc/bluetooth 또는 /usr/sbin)의 수정 날짜 | record.txt 의 값으로 마이크로초까지 되돌린다 |
| /opt/usr | 이 프로젝트는 쓰지 않는다. 혹시 nx500ex 폴더가 있으면 지운다 |

ls, cksum, stat 의 수정 날짜로 보이는 범위에서는 설치한 적이 없는 상태와 같다. PC 의 가짜 루트(공식 펌웨어에서 꺼낸 실제 파일 사용)에서 v2 설치, 재설치, 제거, v1 설치 상태의 제거를 실행하고 전 파일의 경로, 권한, 크기, 수정 시각, inode 를 비교해 동일함을 확인했다.

남는 것 (정직하게)

- 리눅스는 파일과 폴더의 상태 변경 시각(ctime)을 따로 기록하며, 이 값은 프로그램이 되돌릴 수 없다. stat 으로 ctime 을 직접 보면 설치/제거 시각이 보인다.
- 루트 파일시스템을 쓰기 모드로 다시 마운트한 횟수와 시각이 ext4 슈퍼블록에 남는다.
- 폴더 수정 시각은 마이크로초까지 되돌아간다. 이 카메라의 touch 가 나노초 자리를 설정하지 못해, 그 아래 자리(실기에서 300ns)는 0 이 된다. 로그에 note 로 기록된다.
- 카메라 동작에는 아무 영향이 없는 메타데이터다. 이것까지 지워 비트 단위로 같게 만들려면 공식 펌웨어 1.12 를 다시 설치한다. 펌웨어 설치는 루트 파일시스템 이미지를 통째로 다시 쓰므로 그 뒤에는 차이가 전혀 없다.

## 거부하는 경우

- .orig 파일이 공식 펌웨어 원본과 다르면 아무것도 바꾸지 않는다.
- 현재 파일이 이 프로젝트의 래퍼가 아니면(다른 모드) 아무것도 바꾸지 않는다.
- 이미 순정이면 아무것도 하지 않고 알려 준다.

## 사용 방법

1. 이 폴더의 내용(info.tg, nx_cs.adj, nxex_unin.sh, nx500ex-uninstall 폴더)을 SD 루트에 복사한다. 같은 이름의 파일이 있으면 모두 덮어쓴다. 설치 때 생긴 nx500ex-state 폴더가 카드에 있어야 수정 날짜까지 되돌린다.
2. 배터리를 뺐다 넣고, 카드를 넣고 전원을 켠다.
3. UNINSTALL OK 가 나오면 전원을 끈다.
4. 확인하고 싶으면 stage0-probe 를 다시 실행해 existing-mods.txt 를 설치 전 결과와 비교한다.
5. SD 의 nx500ex-state, nx500ex-install, nx500ex-uninstall, nxex_inst.sh, nxex_unin.sh, info.tg.done, nx_cs.adj 를 지우면 카드에도 흔적이 없다.
